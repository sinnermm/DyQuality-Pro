# 抖音画质选择 Pro (DyQuality Pro) - LSPosed 模块

## 项目概述
本模块专为抖音（`com.ss.android.ugc.aweme`）开发，解决官方 ABR 自动码率算法偏向低清晰度、画面压缩模糊的问题。支持用户自主选择 **1K (1080P)**、**2K (1440P)** 与 **原画品质（最高分辨率·满血码率）**，并在追求极致高画质、高码率的同时，彻底杜绝起播卡顿与黑屏问题。

---

## 相比前版（DyQuality 0.9）的关键突破

| 维度 | 前版 DyQuality 0.9 | 本版 DyQuality Pro |
| :--- | :--- | :--- |
| **选流目标** | 同分辨率下“优先低码率省流”（导致画质细节劣化） | **同分辨率下“严格优先最高码率”**，原画模式锁定满血峰值流 |
| **编码策略** | 严格同编码限制（禁止 ByteVC1/ByteVC2 互跨，误判“无安全候选”） | **全面支持 ByteVC1(H.265)、ByteVC2(H.266) 与 H.264**，释放芯片硬解性能 |
| **Hook 层级** | 滞后拦截底层混淆组装类（`X.0FXr` 等），易因混淆变动失效 | **直接在上游数据模型层（`SimVideoUrlModel`）重排序与注入** |
| **播放流畅度** | 播放前临时换流导致预加载缓存未命中，偶发黑屏与缓冲转圈 | **预加载器（Preloader）与播放器同步对齐目标流**，实现高画质秒开不卡顿 |
| **容错机制** | 超分、锐化、HDR 稍有变动即跳过（累计 14 次仅替换 1 次） | 针对图文/直播/纯音频安全放行（Fail-Open），不干扰正常浏览 |

## 核心实现机制

### 1. 选流与打分算法 (`QualityPolicy.java`)
- **原画品质 (MODE_ORIGIN)**：
  按 `短边最大 -> 总像素最大 -> 码率最高 -> 高效编码(ByteVC2/1)` 升序排序，无视分辨率上限，直接匹配服务端下发的顶格流。
- **2K 超清 (MODE_2K)**：
  目标短边为 1440。在 `≤ 1440` 的候选集中匹配短边最大且码率最高者；若视频最高仅有 1080P，自动降级为 1080P 顶格码率。
- **1K 高清 (MODE_1K)**：
  目标短边为 1080。在 `≤ 1080` 的候选集中匹配短边最大且码率最高者；若老视频仅有 720P，自动降级为 720P 顶格码率。
- **自动模式 (MODE_AUTO)**：
  完全放行，交由抖音官方算法决策。

### 2. 预加载对齐（防卡顿关键）
抖音采用预加载（Preloader）机制，在用户滑到下一条视频前，就已经提前根据 `SimVideoUrlModel` 缓存视频分片。
- 本模块在 `SimVideoUrlModel.getBitRate()` 返回候选列表时，将计算出的**目标高画质流直接置换到首位（Index 0）**；
- 预加载器自然抓取目标高画质流进行分片缓存；
- 当用户滑入该视频起播时，直接命中本地高清缓存，实现**高码率秒开无缝播放**。

## 工程构建与安装指南

### 方式一：Android Studio 一键构建（推荐）
1. 用 Android Studio 打开本项目根目录；
2. 等待 Gradle 同步完成；
3. 点击菜单栏 **Build -> Build Bundle(s) / APK(s) -> Build APK(s)**；
4. 生成的 APK 位于 `app/build/outputs/apk/release/` 或 `app/build/outputs/apk/debug/`。

### 方式二：命令行 Gradle 构建
```bash
./gradlew assembleRelease
```

## 模块使用方法

1. **框架激活**：
   - 在已 Root 且安装 LSPosed / Vector 的设备上安装生成的 APK；
   - 在 LSPosed 管理器中启用「抖音画质选择 Pro」，勾选作用域：**抖音 (com.ss.android.ugc.aweme)**；
   - 强行停止抖音并重新打开。
2. **画质切换**：
   - **方式 A（抖音内悬浮球）**：在抖音界面左侧会出现一个精致的半透明「画质」胶囊小球，点击即可弹出画质选择对话框，支持随意拖拽到屏幕任意边缘；
   - **方式 B（桌面独立 App）**：桌面打开「抖音画质选择 Pro」，直接切换全局默认画质。
3. **切换生效时机**：
   - 切换画质后，滑至下一条视频立即生效。
